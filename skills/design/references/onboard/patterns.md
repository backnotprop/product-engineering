# Onboarding patterns


Choose the smallest pattern that gets users to value.

## Empty state

Use when the normal product surface can teach the first action.

Include:

- what will appear here;
- why it matters;
- one clear way to begin;
- a template or import path when it materially reduces work;
- recovery when the state is actually a failure or permission problem.

Do not decorate a blank state before making the next action obvious.

## Template or sample data

Use when creating the first useful object from scratch is slow or conceptually difficult.

- Let users edit something real.
- Make sample status unmistakable.
- Provide a clean path to replace or remove it.
- Avoid examples that imply unsupported capabilities.

## Contextual hint

Use at the moment a feature becomes relevant.

- Point to the exact control.
- Explain the benefit or consequence, not merely the control name.
- Keep it dismissible and accessible.
- Do not repeat it after dismissal or mastery.

## Checklist

Use when activation requires several independent tasks that can be completed in different orders.

- Include only tasks tied to value.
- Show honest progress.
- Allow users to leave and return.
- Do not turn optional enrichment into fake required completion.

## Guided tour

Use only for dense or unfamiliar interfaces where context cannot be learned naturally.

- Keep one tour focused on one workflow.
- Prefer three to seven short steps.
- Allow skip, back, dismissal, and replay.
- Let users interact with the real interface when safe.
- Keep focus management, screen-reader order, and escape behavior correct.

## Sandbox

Use when practice is necessary before high-stakes work.

- Give a concrete objective.
- Use representative data.
- Validate the result.
- Explain how the sandbox differs from production.
- Provide a clear graduation path.

## Returning-user education

Use for meaningful new capabilities, not routine release notes.

- Explain what changed and why it matters.
- Show it near the relevant task.
- Respect dismissal.
- Avoid replaying first-use onboarding.

## Persistent help

Use when concepts remain useful after activation:

- link help near the task rather than only in a separate manual;
- make help searchable and task-focused;
- expose keyboard shortcuts where they can accelerate repeated work;
- keep accessible labels aligned with visible terminology;
- do not use persistent help as an excuse for unclear core controls.

## Measurement

Prefer:

- time to first value;
- completion of the real activation action;
- abandonment point;
- successful return after interruption;
- downstream retained use.

Interpret skip rate carefully. Skipping may indicate experienced users, irrelevant guidance, or excessive ceremony.

Define the eligible population and the real activation event before interpreting rates. Compare time to value, drop-off, and retained use against a baseline rather than optimizing tour completion alone.
